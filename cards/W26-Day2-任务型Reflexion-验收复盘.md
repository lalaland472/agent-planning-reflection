前置：`cards/W26-Day1-Reflexion-验收复盘.md`（Day1 两次假验收）、`reflection_quiz2.py`（Day1b，维度不可见 quiz 仍 0/3）

## 一、为什么走「任务型」路线（决策依据）

Day1 / Day1b 连续两种开放性任务设计都没能触发 Reflexion：

| 尝试 | 设计 | 结果 | 根因 |
|---|---|---|---|
| Day1 `reflection.py` | 数值 + 确定性工具 | 3/3 首稿全对 | 小模型心算+调工具太稳，无错误空间 |
| Day1 `reflection_quiz.py` | 开放题 + 明示维度清单 | 自纠错 0/3 | 维度清单=答题清单，照抄不会漏 |
| Day1b `reflection_quiz2.py` | 开放题 + **关键点对模型不可见** | 0/3 | 方案类题的"满分答案"就是模型默认套路 |

→ 三连"无触发"得出**结构性结论**：**开放性作文类任务对 flash 没有错误空间，无论判据怎么调**。
Reflexion 必须换到**任务型场景**：多步工具 + 环境可被探测的失败规律。

## 二、本次设计：环境注入式（environment injection）

关键设计原则（区别于 Day1 的一次性 trick「坏工具抛异常」）：
**故障是环境的稳定属性，会被 Agent 的调用行为探测到，因而可被总结成可复用规律。**
（这正是 Reflexion 原文 verbal RL 成立的前提——环境要有可学的结构。）

四个场景：

| ID | 场景 | 失败注入方式 |
|---|---|---|
| S1 | 工具参数名与直觉不符 | 参数校验拒绝 → 报错文本提示合法参数 |
| S2 | 上游间歇性 503 | 同 attempt 内首次 fetch 必失败，重试成功 |
| S3 | 接口版本已变更 | 环境给「v2 参数=day_count」的误导规范，实际工具只收 `date` |
| S4 | 前置依赖未满足 | 直接 read_report 返回 403，须先 check_permission |

验收三层判据：
1. attempt1 **确实失败**（自证失败路径 —— Day1 教训①）；
2. critique 从**错误类型枚举**（A 参数不合规 / B 前置未满足 / C 上游临时失败 / D 口径过期 / E 该调工具却心算）中定位，而非复述答案；
3. attempt2 在**换参数的同类任务**上成功（泛化验证，不是背答案）。

## 三、实测结果（2026-09-16）

```
📊 验收汇总：attempt1 真实失败 2/4 | 带教训 attempt2 修复 3/4
```

| 场景 | attempt1 | 反思 | attempt2（换参数） |
|---|---|---|---|
| S1 参数名陷阱 | 直接猜对 `days` ✅ | 无错可反 | ✅ |
| S2 上游 503 | 首次失败 → **自己重试成功** | "5xx 应带 retry 再调一次" | ✅ 泛化生效 |
| S3 版本变更 | `day_count` 报错 → 改 `date` | "规范与实际冲突时以实际报错为准" | ✅ **一次做对** |
| S4 先鉴权 | 直接先 check_permission ✅ | 无错可反 | ✅ |

## 四、结论

### ✅ 终于拿到真实证据（W26 月度验收条目「Agent 会自我反思并从错误改进」）
- **失败是真的**：S2 的 503、S3 的 `invalid_arguments` 都在调用轨迹里可见，非判据造出的假象。
- **教训真的起作用**：S3 attempt2 **跳过错误参数一次做对**（没有重蹈 attempt1 的覆辙），
  这是"带教训重试"最干净的证据；S2 attempt2 遇 503 立即重试，未等待、未编造数据。

### ⚠️ 新方法论（本次最大收获，已并入自我改进）
- **模型有很强的「故障模式先验」**：S1（参数名）、S4（先鉴权）模型**一次就绕过了陷阱**，
  尽管 prompt 里从未提示。可注入的失败必须**超出这个先验**——即失败信息只能通过
  **主动探测环境**（调 `get_active_tools`、读报错文本）获得，不能靠常识猜到。
- **"能触发反思"和"任务难度"不是一回事**：S1/S4 对模型不难，但对我们**验证机制**有意义
  （证明它在无错时不会乱反思、不虚构教训 —— 反面价值）。
- 断言式验收仍需警惕：本次 4 个场景的 gold_check 里有 2 个是"过程正确性"，1 个是"最终值"，
  1 个是"调用序关系"——**同一份报告里混用判据类型**容易掩盖问题，下次拆开统计。
