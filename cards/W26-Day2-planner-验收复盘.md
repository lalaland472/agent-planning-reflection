1. **状态机没接线** → 脏数据，不代表任何事实；
2. **计划与执行语义断裂** → 计划不可校验，属真实工程缺陷；
3. **子目标本身是汇总型** → 合法，不应计入完成率。

**"子目标完成率"这个指标如果不附带判定依据，就是不可信的。**

## 二、核心发现：计划必须可校验（Planner 的致命盲区）

原始 `make_plan` 让模型自由填写 `tool` 字段，不约束取值范围 →
T1 生成的 4 个子目标**没有一个**能与真实调用轨迹对上，且**没有任何报错**。

这意味着：**Planner 产出的计划，自己都无法验证是否被执行** —— 计划不可校验 = 无法知道 Agent 是否偷懒或跑偏。这比"规划效果好不好"更底层，是 Planning 类系统的地基问题。

### 修复（治本三层）
1. **枚举注入**：把真实工具清单（名称+描述）写进 planner prompt，`tool` 只能从枚举中选，不得自创；
2. **解析期校验**：非法工具名 → 置 `None`，原值存 `tool_illegal` 便于审计（不静默吞掉）；
3. **汇总型子目标显式豁免**：`tool: null` 且描述属汇总/作答语义 → 不参与 done 判定，避免虚假拉低完成率；
   反之，动作型语义却没绑定工具 → 标记 `invalid`（计划缺陷），暴露而非掩盖。

  正确判据应是「读满 3 篇 **或** 如实说明库内不足」。

### 分任务结论（稳定不变）
| 任务 | 特征 | 谁赢 |
|---|---|---|
| T1 查 3 篇并总结 | **步骤不可预知**（不知库里有啥、要试几组检索词） | planner 唯一稳定收敛，回答带逐条子目标结论 |
| T2 跨论文对比 | 步骤可预知（读两篇 → 对比） | noplan 完胜（4~5 次 vs planner 12~13 次） |
| T3 检索-筛选-计算 | 完全固定三步 | noplan 完胜（3 次 vs planner 14~15 次） |

> **规划在何任务值得？仅当「步骤不可预知」时值得。**
> 步骤固定或可预知的多步任务，显式规划是纯开销 —— T3 里 planner 用了约 5 倍工具调用、约 4~6 倍 token，成功率却和 noplan 一样。
> → 工程建议：**默认 ReAct，检测到"探索型/不确定性高"的任务信号（库大小未知、需多轮试错）再切规划模式**。

## 四、复验发现的两个代码 bug（2026-09-18 已修复 ✅）

### bug-1 证据链串号：同名工具多次调用时取错观测
- **现象**：T2 子目标 [3] 是「读 Self-RAG」，但依据打印的是 `Reflexion (2023)` 的摘要。
- **根因**：旧代码 `next(c for c in calls if c["name"] == hit)` 永远取**第一条**同名调用，不区分是第几次调用。
- **修法**：引入**调用序号游标**（`used` 集合）——每条子目标只认「尚未被前序子目标占用」的调用（前缀归因），并在依据里标注 `[调用#N]`。
- **验证**：修后 T2 明确输出 `[2] read_paper → Reflexion[调用#10]`、`[3] read_paper → Self-RAG[调用#11]`，串号消失。

### bug-2 空结果也算 done：「调了工具」≠「拿到了东西」
- **现象**：T3 子目标 [1] `search_papers(topic='method')` 返回 `count: 0, results: []`，却被判 `done`。
- **根因**：`done` 的判据只看「工具被调用过」，不看返回载荷。
- **修法**：`done` 拆三档 —— **done / empty / todo**；新增 `_is_empty()` 判定空载荷（空 dict、`count=0`、`results/notes/items/papers` 为空、`saved=False`、空串）。
  调用发生但返回空 → 标 `empty`（**执行可校验 ≠ 结果有效**），且 empty **不计入有效完成率**。
- **验证**：修后 T3 输出 `子目标有效完成 3/4（另有 empty 1）`，[1] 标 `◍ empty(空结果)` 并附原始载荷。
- 单测：`_is_empty` 9 个用例（含 `{}`、`[]`、`count:0`、`saved:False`、`4047`）全部通过。

### 这两个 bug 的层级意义
首验只发现了「计划不可校验」（计划与执行语义断裂）。
复验再往下一层发现：**「执行可校验」也不等于「结果有效」** ——
三级递进：`计划可校验` → `调用可归因`（bug-1）→ `结果有效性`（bug-2）。
