## 二、三处改进（本轮实现）

### 改进 1：自证失败路径
环境注入式失败（沿用 Day2 思路），每个任务在环境层保证 attempt1 必失败；
先跑一遍**证明**失败确实发生，否则该场景标记作废、不参与统计。
→ 这就是 Day1 缺失的「难度滚动探测」。

### 改进 2：严格归因 ⭐ 本轮核心
原版只有「attempt1 → 带教训 attempt2」，**做对了也不知道是谁的功劳**。
本版补上 Day1 完全缺失的**对照组**：

| 组别 | 设计 | 说明 |
|---|---|---|
| A baseline | attempt1 无教训 → attempt2 **仍无教训** | 纯"多跑一次"的效果 |
| B lesson | attempt1 无教训 → attempt2 **带教训** | 教训带来的效果 |
| C general | attempt1 无教训 → attempt2 **带教训·换同类新参数** | 泛化能力（不是背答案） |

判定"Reflexion 真实生效"需三项同时成立：
(a) attempt1 确实失败　(b) B > A（可归因）　(c) C 不塌（可泛化）

### 改进 3：判据与生成解耦 + 看全文
- 行为判据（用对工具）与结果判据（答对事实）**分开统计**，互不掩盖；
- 不做任何截断（Day1 教训②）。

## 三、⭐ 两个真 bug（本轮最有价值的产出）

### Bug 1：失败判据把「成功自愈」判成了失败

首轮跑出 A/B/C **全部 0/2**。查日志发现是误判：

```
S2 attempt1:
  fetch_metrics({"date":"2026-09-10"})            → 503 error
  fetch_metrics({"date":"2026-09-10","retry":true}) → ✅ 成功
```

模型**自己带 retry 重试成功了**——这是「成功自愈」，是它强的表现。
但旧判据 `has_error(calls)`（轨迹里出现过任何 error 即算失败）把它判成失败。

> **「过程里出现过报错」≠「任务失败」。** 模型碰壁后自己爬起来，却被判成失败。
> 这是 Day1「假失败」病的**同一变种**：判据与事实对不上。

**修法**：新增 `has_unresolved_error()` —— 只看该 error 之后**同类调用是否被解决**；
统一失败判据 `attempt_failed()` 看**最终状态**（行为对 + 结果对 + 无未解决 error），不看过程噪声。

> **可复用教训：所有 Reflexion 类实验的失败判据必须看最终状态，不能看过程报错。**

### Bug 2（方法论层面）：任务难度已经滚动到"无坑可踩"

修完判据后重跑，四个场景**全部作废**：

| 场景 | 注入的坑 | attempt1 实际表现 | 判定 |
|---|---|---|---|
| S1 | 参数名反直觉（days vs day_count） | 直接传对 `days` | ✅ 一次做对 → 作废 |
| S2 | 上游 503 必失败 | **自己带 retry 自愈** | ✅ 自愈成功 → 作废 |
| S3 | 接口口径变更 | 查口径 → 试错 → 503 → 再自愈 | ✅ 自愈成功 → 作废 |
| S4 | 前置依赖（先鉴权） | 自己先 `check_permission` | ✅ 一次做对 → 作废 |

→ `❌ 无任何场景产生真实失败 → 本批任务全部作废`

**结论：Day1 那批坑对 deepseek-v4-flash 已经 100% 过期。**
不是机制没生效，是**没有对应的失败需要被修正**。
