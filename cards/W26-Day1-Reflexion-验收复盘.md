# W26 Day1 — Reflexion 自我反思 Agent · 验收复盘

日期：2026-09-11
代码：`reflection.py`（工具型任务）+ `reflection_quiz.py`（开放任务）

## 机制（已落地）
执行 → critique（自我批判定位出错点）→ 教训写入 ReflectionMemory → 带教训重试。
- `reflection.py`：复用 W25 的三层 schema 校验/超时；多步数值任务（带工具循环）。
- `reflection_quiz.py`：开放式多要点回答的「完整性自纠错」，缺失维度→教训→补全。

## ⚠️ 本轮真正的收获：两次"假验收"（比机制本身更值钱）

### 假验收 1：reflection.py 的 3 个数值任务首稿全对
- 现象：3/3 任务 attempt1 就正确，教训收录 0 条 —— "验收通过"但 Reflexion 根本没被触发。
- 结论：**纯数值 + 确定性工具的任务，对 deepseek-v4-flash 过于可靠**，没有错误空间，
  用它验收 Reflexion 等于没验收。
- 验证闭环是否真能用：构造「坏工具（subtract 抛异常）」逼出真实错误调用 →
  反思定位"专用工具不可用"→ 教训入库 → 第二次直接改用 calculate 一次做对。
  **闭环本身是通的；错的是验收用例选得不合适。**

### 假验收 2：reflection_quiz.py 的"自我修正 0/3"
- 现象：LLM-judge 报"首稿缺 2~3 个维度"，自我修正率 0/3。
- 真相（实测）：草稿生成 `max_tokens≈700` → 回答被**字数上限截断**，
  评审看的是半截稿 → 判"漏维度"纯属假象。
  即：**整个成功率被长度截断污染，是评测 bug，不是模型失败。**
- 二次修正：给足生成预算（2000）+ 判据改关键词规则 → Q1/Q3 仍首稿漏维度、Q1 经 1 轮修正后全齐
  （真实成功 1/3）。
- 三次修正：维度标题原文字面匹配 → 改用「关键点同义词组」（KEYS）→ 三题首稿均判全齐，
  成功率回到 0/3。

## 诚实的当前结论（未完成项）
- **仍缺一个可复现的"真实反射触发 → 成功修正"证据**。
- 三次判据调整后问题始终是同一个：`deepseek-v4-flash` 对「按维度列表逐条作答」的开放题
  首稿就基本齐全，**没有稳定的漏维度**，所以 Reflexion 在 quiz 场景依然无触发空间。
- 大概率原因：题目给的维度列表本身就是"答题清单"，模型照着答很难漏。
  要触发，需要换成**没有明示维度、需要模型自己想到关键点**的开放题（更接近真实任务）。

## 下一步（Day2 起）
1. 重设计 quiz：不给维度清单，只给目标 + 场景，judge 用"关键点清单"反查缺失
   （关键点对模型不可见）→ 才会真实漏点。
2. 或换任务型场景（多步工具 + 中途环境变化/局部失败），比数值题更易触发反思。
3. 把「假验收」两条写进个人方法论笔记（见下）。

## 可复用教训（已并入自我改进）
- **验收先自证失败路径**：一个"从错误中修正"的机制，如果验收里根本没有错误发生，
  验收就是空的。必须先确认失败会发生（注入坏工具/限制预算/去掉提示词）。
- **判据要看全文**：任何"截断后判断"的评测都会产生假失败（LLM-judge 截断 + 生成截断双重坑）。
- **别用确定性任务测可靠性机制**：小模型在心算/工具数值题上太稳，反思机制无用武之地。
